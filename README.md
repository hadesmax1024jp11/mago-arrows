# 馬哥箭頭逃脫 · Mago Arrows

**一款單檔、離線可玩的箭頭邏輯解謎遊戲。**
點一下箭頭，它就沿著自己的軌道整條滑出棋盤 —— 前提是箭尖正前方那條直線完全淨空。

### ▶︎ [開始試玩](https://hadesmax1024jp11.github.io/mago-arrows/)

</div>

## 玩法

盤面上每一條折線都是一支箭頭，**箭尖就是它要衝出去的方向**。

1. 點一下，它會沿著**自己的身體軌道**整條滑出棋盤（頭先出去，身體跟著同一條路線走）。
2. 唯一條件：**箭尖正前方那條直線，到棋盤外之前完全沒有東西**。
3. 被擋住就撞上去，扣一顆愛心。三顆用完可以免費補滿，或整關重來。
4. 所以真正要做的事只有一件：**找出正確的清除順序**。

### 為什麼不可能卡死

移除一支箭頭只會**釋放**格子，永遠不會新增阻擋 —— 可走的箭頭集合只會單調變多。
只要每一步都走合法的move，就不可能把自己玩進死局。
失敗只來自命數，不來自順序，所以卡住的時候「重來」重置的是愛心，不是解法。

難度純粹來自一件事：**在幾百支箭頭裡看出那兩三支現在走得掉的**。

## 特色

- **單檔 399 kB**：雙擊 `index.html` 就能玩，無需伺服器、無外部資源、可離線
- **關卡無上限**：前 300 關在建置時烘焙好，第 301 關之後由同一套生成器現場產生
- **每一關都保證有解**：不是事後求解驗證，而是生成方式本身保證（見下）
- **第 N 關永遠是同一關**：生成器以關卡號為種子，所以難度可以預先顯示、星數才有意義
- **每日一關**：以日期為種子，全世界同一天玩到同一盤
- **關卡地圖 / 成就 / 週榜 / 提示與格線道具 / 六組主題 / 中英雙語**
- **馬哥**：場邊吉祥物，會在棋盤外探頭喊話，並且**保證不會擋到盤面**（見下）
- 大盤面可以**拖曳平移**與**雙指縮放**，開場一定先縮到整盤看得完
- **背景音樂**：程式即時合成的環境音，沒有音檔、不會重複（見下）
- **開場儀式**：關卡卡片 + 所有箭頭從盤外逆轉飛回原位；不想看可以點一下跳過
- **過關慶祝**：全螢幕動畫、星星逐顆蓋章，1.5 秒後才滑出結算

## 怎麼生成關卡：逆向建構法

核心只有一句話：**每放入一條蛇時，都要求「它的出場射線在當下是淨空的」。**

```
for i in 1..N:
    窮舉所有 (頭部格, 朝向) 使得「頭部往該方向到出界」的路徑全空
    挑一個，然後從頭往後長出蛇身（第一節必定在頭的正後方，且不可壓到自己的射線）
```

移除順序 = 放入順序的**反向**。理由：第 i 條放進去時射線是乾淨的，只有第 i 之後放的
東西可能擋住它；反向移除時那些都已經離場了。所以每一關**數學上保證有解**。

### 六組筆觸

每走一步用 `右轉 : 直行 : 左轉` 的權重擲骰決定下一步：

| 筆觸 | 長度 | 右 : 直 : 左 | 畫出來的樣子 |
|---|---|---|---|
| 直尺 Ruler | 5–26 | 1 : 100 : 1 | 長直線；撞牆後沿邊界同向轉，形成階梯回紋 |
| 素筆 Plain | 7–28 | 1 : 5 : 1 | 中庸，最好認 |
| 小徑 Lane | 6–26 | 1 : 9 : 1 | 少彎長路 |
| 亂麻 Tangle | 3–70 | 1 : 2 : 1 | 短而彎，用來收拾零碎空間 |
| 蛇行 Zigzag | 6–20 | 100 : 5 : 100 | 鋸齒（轉彎方向交替） |
| 迴圈 Coil | 3–64 | 400 : 400 : 1 | 單向繞圈 |

名字取的是「畫出來的樣子」而不是參數，因為**碰撞約束會把行為拉向名字**：
偏直行的會被牆逼著轉，偏轉彎的會撞到自己而退回直行。實測轉彎率跟設定值差得很遠，
但視覺特徵跟名字完全對得上。

一關會跑 1～3 個 pass：第一個用長箭頭鋪骨架，後面的用高轉彎率的小箭頭填零碎空間。

### 補洞

貪心塞到最後一定會剩幾個洞（新蛇至少要兩格，且頭部前方要淨空）。所以多加一道補洞：
對每個空格輪流試三種補法，**每補一格就重跑一次可解性驗證**，破壞解法就退回換下一種。

1. 接在某條蛇的**尾端**（頭與方向不變）
2. 接在某條蛇的**頭前面** —— 那一格變成新的頭，出場方向跟著轉向
3. 兩個相鄰空格**配成一條新的兩格蛇**

加上第 2 種之後，8×8 的一次成功率從 22% 跳到 99%。

> 全滿的盤面為什麼還有解？因為頭部貼著邊緣朝外的蛇，出場射線長度是 0，
> 不需要任何空格就能走。它先出去之後就替後面的蛇讓出通道。
> 生成器會刻意把這種落點**排到最後面**，開局的解法數才壓得下來。

### 難度：只有一個變數

**難度 = 盤面上所有箭頭佔用的格數總和。** 三個門檻 `700 / 1300 / 1850` 切成四段：

| 分段 | 佔用格數 |
|---|---|
| 悠閒 Gentle | 190 – 699 |
| 認真 Tricky | 700 – 1299 |
| 硬派 Brutal | 1300 – 1849 |
| 無情 Merciless | 1850 – 2200 |

棋盤面積、箭頭數、彎折數、解題深度**一律不參與判定**。
好處是「調難度」＝調三個數字，不用重做關卡。

排程用一個**30 關的循環模板**，每格是「這一關允許的區間」。設計意圖是
**穩態曲線 + 里程碑尖峰**而不是單調遞增：實測第 31 關之後的分段比例是
**63 / 26 / 8 / 3 %**，而且「無情」只出現在 10 的倍數關。
玩家永遠感覺難度有起伏，實際負載是平的。

每 5 關安排一個**圖形關 ◆**：正方形盤面、圖形只填一半，分段不變但視覺密度砍半
—— 節奏上的減壓閥。圖形有 **40 種**，分五類：

| 類別 | 圖形 |
|---|---|
| 經典 | 愛心、星星、月亮、幽靈、竹子、熊貓、雲、錢幣 |
| 食物 | 壽司捲、拉麵、甜甜圈、鳳梨、冰淇淋、漢堡、蛋糕、草莓、蘑菇、珍奶 |
| 建築 | 城堡、鐵塔、寶塔、房子、火箭、帆船、風車、拱橋 |
| 角色 | 機器人、忍者、貓臉、小恐龍、外星人、史萊姆、頭盔、巫師、兔子、熊 |
| 物件 | 皇冠、鑰匙、鑽石、花 |

角色全部是原創通用形象，沒有引用任何既有作品。

挑圖形的規則分兩段：新手期的五個圖形關（10/15/20/25/30）走固定順序，
第一印象可控；之後從**「裝得下這一關格數」的圖形裡均勻抽**。
後面這件事很重要 —— 早期版本是「抽一個，裝不下就退回矩形」，
結果 5 的倍數關有四分之一根本沒圖形，稀疏的圖形（雲、鐵塔）幾乎永遠抽不到，
最常出現的圖形是最少的十倍。改成先篩候選再抽之後，179 個圖形關用到 38/40 種圖形，
最常出現的那個只用了 8 次（平均 4.5 次），而且每個 5 的倍數關都排得到圖形。

盤面邊長上限定在 **55**：掃過 52～64 之後，52 會讓最硬的幾關沒圖形裝得下，
64 只多換到兩個圖形卻讓 360px 手機上每格從 6.1px 掉到 5.3px。
另外圖形的填充率不能超過 82% —— 太密的圖形放大後就只是個圓角方塊，
「密度砍半」的意義會消失（漢堡跟皇冠第一版都踩到 87%，得靠真正的空洞畫層次）。
這三件事都有測試盯著。

### 邏輯難度是平的

生成候選時就照「任一時刻可走的箭頭數」挑，目標壓在 **2.8** 附近。
所以箭頭數從 6 支長到 270 支，任一時刻能走的仍然只有幾支 ——
**難度上升的實質是視覺搜尋成本**，不是推理深度。死局風險永遠是 0。

## 馬哥：對話框絕對不能壓到盤面

這是一條硬性約束，做法不是「往外挪一點」而是幾何鎖定：

- 出場前量測棋盤四周剩下的空白帶
- 站左右側時，「馬哥 + 對話框」整組限制在該側的**直帶**內 → 橫向不可能碰到棋盤
- 站上下側時，整組限制在該側的**橫帶**內 → 縱向不可能碰到棋盤
- 對話框用 `nowrap` 單行、寬度由字數精算後直接寫死，計算與渲染完全一致
- **算不出安全位置就這回不出現**，寧可沉默也不硬塞

測試對 4 種螢幕 × 5 種盤面 × 4 種姿態 × 4 句台詞共 **454 種擺法**做矩形交集檢查，0 次碰到盤面。

## 聲音：全部是程式合成的

音效與背景音樂都沒有音檔。塞一首 MP3 進來（base64 之後 1.5 MB 以上）會直接毀掉
「單檔、離線、400 kB」這件事，所以全部用 Web Audio 即時生成。

BGM 是極簡環境音，兩層：

- **和聲墊**：兩個微微離調（±4 音分）的三角波，每 8 秒換一個和弦，慢起音慢收
- **點狀音**：小調五聲音階的稀疏音符，音高與時間點都是隨機的

用五聲音階的理由是它沒有半音衝突，所以隨機取音永遠不會刺耳 ——
也永遠不會重複，不會有循環樂句聽久發膩的問題。音量壓在音效之下、音域也錯開
（墊音在低頻、音效是高頻短音），所以不需要做 ducking 就不會互相蓋掉。

排程用 **lookahead** 而不是 `setTimeout` 逐音觸發：每 250 ms 醒一次，
把未來 1.4 秒要發的音一次排進 Web Audio 自己的時間軸。
`setTimeout` 在分頁卡頓或切到背景時會歪掉，Web Audio 的時鐘不會。

## 開場動畫：為什麼是 CSS transform

每一關開場時所有箭頭會**從盤外沿著自己的出場方向飛回原位**，依生成順序一波波蓋上來。
順序是對的，因為生成器放入第 i 條蛇時要求它的出場射線在當下淨空 ——
所以照放入順序飛回來，每一支的來路都只會經過還沒到位的空格。

實作上沒有沿用 `escape` 那套逐格改 `strokeDashoffset` 的做法。
大盤面有 270 支箭頭，270 個元素 × 每格兩次 style 寫入會把主執行緒吃光。
改用 `transform` + `opacity` 交給瀏覽器自己補間，JS 只在頭尾各碰一次 DOM。
代價是箭頭飛行時是整條剛體平移而不是沿折線爬回來 —— 但同時淡入、0.4 秒到位，
看起來是「倒帶」而不是「穿過別人」。

三件配套的事：`prefers-reduced-motion` 直接跳過整段動畫；
箭頭數多的時候縮短飛行距離（重繪面積小一點）；點畫面任何地方可以跳過
（一關一秒，重玩同一關的人會被這一秒煩死）。

  bake.js             生成並打包前 N 關

```bash

python3 tools/build.py        # -> index.html
npm install jsdom && node tools/test.js
```

### 關卡包編碼

前 300 關直接內嵌，但 JSON 太肥，所以改成**欄位分流 + 位元打包 + gzip**：
每支箭頭的頭部座標、出場方向、蛇身步數各自成一個串流，蛇身則存**轉向**
（直行 / 右 / 左，2 bits）而不是絕對方向 —— 多數步是直行，熵只有 1.36 bit。
25,553 支箭頭壓成 **124 kB**，瀏覽器端用內建 `DecompressionStream` 解開。

### 測試怎麼跑

jsdom 沒有排版引擎也沒有 SVG 幾何，所以測試自己補了三塊：

1. **`getPointAtLength` / `getTotalLength`** — 真的解析折線座標，用來驗證箭頭朝向與 dash 參數
2. **`getBoundingClientRect`** — 按真實比例補上版面幾何，用來驗證馬哥的避讓邏輯
3. **`pointer-events` 的 CSSOM 繼承推導** — 每次點擊前先確認「玩家真的點得到」

直接對元素 `dispatchEvent` 會跳過命中測試，那正是「整盤點不動卻測試全綠」的來源。

目前 **123 項**，涵蓋：生成器決定性與資料完整性、關卡包解碼與生成器輸出**逐格比對**、
難度模型不變量、圖形關的排程與多樣性、真實點擊與動畫、道具、
關卡地圖 / 每日 / 成就 / 週榜、即時生成、大盤面平移縮放、馬哥避讓矩形檢查、
四種螢幕的開場視野、開場動畫（含 inline style 有沒有清乾淨、跳過機制）、
過關慶祝與結算的先後順序、BGM 排程器有沒有真的收掉、版本戳。
